# DI engineering decisions

Decisions where the [report](REPORT-EXTRACTION.md) is silent or leaves implementation open. Each is **EXPERIMENTAL** until an evaluation or review supports it. Changing a decision = new entry or status change, never a silent edit.

| ID | Decision | Rationale | Status |
|---|---|---|---|
| D-001 | Tooling runs on Node ≥ 22.18 with native TypeScript type-stripping (erasable syntax only, no build step). Playwright pinned to 1.56.1 to match the pre-installed Chromium build; axe-core, Lighthouse, Ajv (JSON Schema 2020-12), `yaml`. | Report examples are Node/TS; no-build keeps scripts runnable inside the skill. | EXPERIMENTAL |
| D-002 | Third-party screenshots, frame sequences, full ARIA/axe/Lighthouse reports live in git-ignored `research-artifacts/`. Their SHA-256 hashes and capture metadata are committed in `datasets/raw/**/manifest.json`. | Report P12/W4/W13: no redistribution of others' visuals; keep evidence traceable. Cost: OBSERVED evidence must be re-captured to be re-viewed. | EXPERIMENTAL |
| D-003 | Committed raw data contains **no page copy**. Text is reduced to length, word count and script (latin / arabic / mixed / digits). Font family names, measurements and structural facts are kept. | Avoid copying copywriting; shrink the prompt-injection surface of stored data. | EXPERIMENTAL |
| D-004 | Observations are split by authorship: `verified.json` is produced deterministically by `scripts/normalize.ts` and never hand-edited; `analyst.json` holds OBSERVED and INFERRED entries with evidence pointers. | "Prefer deterministic collection over manual guessing"; keep fact and interpretation in separate files. | EXPERIMENTAL |
| D-005 | Reference IDs carry their split: `ref-NNN` extraction, `val-NNN` validation, `hol-NNN` holdout. | Makes leakage mechanically testable. | EXPERIMENTAL |
| D-006 | Evidence thresholds. A `principle` needs ≥ 2 independent extraction references (confidence `low`), ≥ 3 for `medium`, ≥ 4 spanning ≥ 2 archetypes with no unresolved counterexample and a consistent validation check for `high`. One reference → `signature` (do not generalize) or `hypothesis`. Two references from the same company/studio count once. External standards (W3C, WCAG, Unicode, CSS specs) may ground an `invariant`. | Report P42 asks for "≥ 3 independent references"; external standards are needed where the corpus cannot speak (e.g. bidi algorithm). | EXPERIMENTAL |
| D-007 | Rule lifecycle: `candidate` (not in skill) → `provisional` (in skill, no human review yet) → `accepted` (human-reviewed) → `weakened` / `rejected` / `deprecated`. Only `provisional`, `accepted`, `weakened` compile into the skill. | DI v0.1 has no human reviewer yet; honesty about that is required. | EXPERIMENTAL |
| D-008 | Holdout sealing: holdout sites are listed in `datasets/corpus.yaml` (URL + context only) and are not captured until the v0.1 rule set is frozen (freeze commit recorded in the journal). Tests fail if a rule cites `hol-*`. | Report P5/W7. Limitation: the generating model may know famous sites from pre-training; DI only prevents *session-evidence* leakage. | EXPERIMENTAL |
| D-009 | Lab performance numbers collected in this container travel through an egress proxy. They are environment-relative: used for within-corpus comparison and for stable facts (bytes, request counts, font files), never as absolute claims about a site. | Proxy latency distorts timing metrics. | EXPERIMENTAL |
| D-010 | Consent banners: the collector clicks a visible privacy-preserving option ("reject all", "necessary only", "رفض") if one exists, otherwise captures as-is; the action is logged. Bot challenges/CAPTCHAs are never bypassed — the page is marked blocked. | Realistic capture without consenting to tracking; no detection evasion. | EXPERIMENTAL |
| D-011 | Emulation: Chromium for all captures, DPR 1; mobile viewport adds a mobile Chrome user agent, `isMobile`, `hasTouch`; tablet adds `hasTouch`. WebKit/Safari behavior is UNVERIFIED. | Measurement consistency; only Chromium is pre-installed. | EXPERIMENTAL |
| D-012 | Knowledge has one source of truth: rule YAML in `datasets/rules/`. Skill references are compiled by `scripts/build-skill.ts`; hand-written framing may explain how to apply rules but may not introduce new rules. | No orphan rules; provenance stays attached. | EXPERIMENTAL |
| D-013 | Benchmark outputs are dependency-free static HTML/CSS/JS. | Comparable, offline-renderable, no framework confound. | EXPERIMENTAL |
| D-014 | No model identifiers are written into repository artifacts; generation conditions are labelled `control` / `treatment` with "same model, same settings" asserted by the harness. | Environment policy; conditions matter more than names (report P39/W14). | EXPERIMENTAL |
| D-015 | Version identity = `metadata.version` in `SKILL.md` + `CHANGELOG.md`; release commits are titled `release: DI vX.Y.Z`. Git tags are not pushed in v0.1. | Branch-only push policy in this environment. | EXPERIMENTAL |
| D-016 | Untrusted content: the collector stores no free text; analysts treat page text as data; instruction-like content found on a site is logged as an incident in the journal and ignored. | Report P37, prompt-injection safety. | EXPERIMENTAL |
| D-017 | Robots/terms: `robots.txt` is fetched before capture; a path disallowed for `*` is not captured automatically and the reference is marked blocked. Capture is low-rate: one load per viewport plus a handful of interactions, no crawling. | Report P11. | EXPERIMENTAL |
| D-018 | All four benchmark viewports are captured for every captured reference; interaction captures (menu, hover, focus, scroll frames) at 390×844 and 1440×900 only. | Cost control; the two extremes carry most responsive information. | EXPERIMENTAL |
| D-019 | Docs and code are in English; Arabic appears where it is the subject (RTL rules, test strings, briefs). | Maintainability for mixed teams. | EXPERIMENTAL |
