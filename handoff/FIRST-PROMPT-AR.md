## قرارات المعمارية (نهائية)
- اللغة: TypeScript على Node.js (Python فقط لأدوات متخصصة عند الحاجة).
- المتصفح: Playwright للأتمتة واللقطات والاختبار المتجاوب والتحقق البصري.
- تخزين المعرفة: ملفات JSON مُصدَّرة ومُنسَّخة، بادئًا بملف تصدير DI وschema الخاص به.
- مزوّد الذكاء الاصطناعي: Together AI للعرض الأولي، مع عدة نماذج قابلة للاختيار، لكن نموذج رئيسي واحد فقط نشط لكل جلسة مستخدم. مفتاح API في متغير بيئة TOGETHER_API_KEY ولا يُكتب في أي ملف أو commit.
- JEV: مساعد خفيف مستقبلي للمهام التشغيلية وتحسين الموارد، وليس النموذج المحادثي الرئيسي. صمّم نقطة توسعة له فقط ولا تنفّذه.
- تركيز المنصة: فهم العميل ذكيًا، جمع المتطلبات التفاعلي، التصميم الإبداعي، تطوير المواقع والبرمجيات، المعاينة الحية، والتحرير البصري.

1. اقرأ بالكامل: C:\Users\ksa\Desktop\DI-Source\handoff\README.md ثم INTEGRATION.md ثم SETUP-AR.md، ثم evals\results\cycle-01\REPORT.md، ثم CHANGELOG.md وdocs\DECISIONS.md.

5. قدّم لي وثيقة معمارية مقترحة (ملف واحد) تغطي: بنية المجلدات، الحزم/الوحدات، طبقة المزوّدات (Together AI + اختيار النموذج + قاعدة نموذج رئيسي واحد لكل جلسة)، مخزن المعرفة (JSON مُنسَّخ + استيراد ملف DI)، أداة التحقق عبر Playwright (تغليف verify() من DI كأداة)، المعاينة الحية والتحرير البصري، تدفق جمع المتطلبات، نقطة توسعة JEV، الأمان (إدارة المفاتيح، المحتوى غير الموثوق من الويب كبيانات لا كتعليمات، عدم التعديل الذاتي للمعرفة)، الاختبار، ومراحل التنفيذ مع معايير القبول لكل مرحلة، والأسئلة المفتوحة.
