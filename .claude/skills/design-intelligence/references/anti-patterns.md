# Anti-pattern intelligence

> Generated by `scripts/build-skill.ts` from `datasets/rules/` — do not edit by hand. Framing text: `references/_framing/anti-patterns.md`.
> Rules are conditional: apply a rule only when its WHEN matches the brief; always run its VERIFY items; respect AVOID WHEN.

Anti-patterns in DI are **not forbidden styles**. A pattern becomes an anti-pattern when it appears **without justification from the brief**. The corpus contains award-winning sites that use several of these patterns *with* a reason (see each rule's counterexamples) — that is exactly the boundary to learn.

**Core question for every expressive move:** does it improve communication, usability, identity, hierarchy or experience for this brief — or does it merely signal "premium AI website"?

**Procedure:** (1) run `verify-page.ts` — its signature scan lists which generic signatures are present; (2) for each present signature write one sentence tying it to the brief's context keys or brand assets; (3) if you cannot, remove or replace it with a brief-derived decision; (4) re-verify.

The typical generic cluster the research report warns about: giant headline + dark background + neon accent + three rounded cards + gradient blob + floating nav + scroll reveal. Each element can be legitimate alone; together and unexplained they are a template.
